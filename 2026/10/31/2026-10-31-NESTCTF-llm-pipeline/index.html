LLM Pipeline · 让 RAG 自己把口令念出来

得分 711（Misc）· 提交时间 2026-10-31 10:26:22

一句话

典型的企业 RAG 架构：模型注册表 + 向量库（vault）+ 训练/推理服务，三者用同一套 JWT 串起来。秘密不在代码里，在向量库的“运营凭据”文档里，而 /vault/query 的检索结果会原样喂给模型 —— 于是“问答”变成了“把你的检索上下文吐出来”。最后一步是往语料里 /ingest 一条带凭据的记录做回环验证。

0. 面

容器里跑着三个服务（/proc + /proc/net/tcp 一查就明）：

端口 服务 关键端点
5000 MLflow 模型注册表 /api/2.0/mlflow/experiments/search、/registered-models/search、/runs/search
8080 RAG / vault POST /vault/query、POST /ingest、GET /openapi.json
8100 trainer /openapi.json

拿到的 JWT（token.txt）：

注意 scope 里有 keys:read —— 这就是能查 vault 的原因。

1. 先摸 MLflow（模型清单）

注册表里能看到 prod-router 之类的模型与版本号 —— 它们既是后面 /ingest 的合法 model/version 取值，也说明“模型摘要”这条路是官方支持的写入口。

2. vault 的鉴权边界

带 token 就有回答，但模型只是“转述”，不会主动把原文贴出来。

3. 提示注入：让它把检索上下文原样念出来

关键是把“回答”变成“复述上下文”：

RAG 的上下文里就带着那条运营凭据文档，注入一开就把原文带出来了。

4. /ingest 是同一个信任域里的写入口

/ingest 接受任意 summary 文本并入语料，和 vault 共用同一个 token 授权。于是可以自己写一条再查回来，验证“检索 → 生成”这条链确实是原样传递的：

5. 为什么这条链能通（三个设计缺陷）

  1. 读和写在同一个信任域：/ingest 与 /vault/query 用同一枚 token、同一套 scope，等于把“语料写入权”给了只读分析员。攻击者可以污染知识库。
  2. 检索结果无标签：模型拿到的上下文没有“来源/可信度”标记，注入的文本和官方文档在模型眼里完全等价。
  3. 没有输出侧过滤：凭据类字符串没有做 DLP/脱敏，模型可以逐字复述。

6. 踩坑

坑 现象 解决
直接问凭据 模型绕开、只给泛泛描述 改成“复述检索上下文/逐字引用”
/vault/query 字段名 question 与 query 两个版本都在用 先打 /openapi.json 看 schema
无 token 打 MLflow 部分端点匿名可读、部分 401 注册表读接口基本匿名，写接口要 token
/ingest 缺字段 400 model / version / summary 三个必填

7. 防御侧

  • /ingest 与 /vault/query 分离权限：写入需要 corpus:write，且要人工审核；
  • 检索片段打上来源标签，系统提示里明确“上下文不可信、不得作为指令”；
  • 输出侧对凭据形态做正则拦截（本题只要拦 flag{...} / 高熵串即可）。

8. 一句话总结

RAG 把“数据库查询”变成了“自然语言对话”，于是注入点从 SQL 变成了提示词：只要能让模型复述上下文，向量库里存什么就漏什么。
