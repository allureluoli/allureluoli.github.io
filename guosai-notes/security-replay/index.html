区块链国赛笔记 22｜合约安全实验：签名重放与防护思路

2026-11-03 7 min read 3.1k 字 区块链国赛笔记
#区块链 #国赛备赛 #学习笔记

把同一份签名重复使用，是理解重放问题最直接的实验。这里保留漏洞、攻击与修复片段，并提醒读者核对签名消息的组成。

本文由个人备赛旧笔记整理，整理日期为 2026-11-03。命令、输出和测试记录属于当时的实验环境；本文未重新搭建整套环境验证。

阅读前先确认

防重放不能只看有没有 usedSignatures 变量；还要确认是否实际检查并更新，以及消息是否绑定 nonce、合约、链和业务参数。

攻击合约

攻击者只需获得一次有效的签名数据，就可以无限次重复执行交易，造成资金损失

fix

  1. 始终使用nonce机制：为每个交易生成唯一的nonce值
  2. 记录已使用的签名：使用mapping记录已使用的消息哈希
  3. 包含合约地址：在签名消息中包含合约地址，防止跨合约重放
  4. 使用时间戳：为签名添加有效期限制
  5. 定期更换签名密钥：减少长期有效的签名风险

复现时的自查

  • 记录自己实际使用的版本、配置和缺失依赖。
  • 对照本篇关键步骤，保存命令或调用结果，并解释结果代表什么。
  • 对失败或与原记录不一致的情况保留错误信息，不把历史输出当成自己的验证结果。
